Milestone Four Narrative

Artifact Description

I selected an artifact known as the MongoDB CRUD Dashboard, which I initially developed when I was taking CS 340. This artifact shows the animal shelter information and enables filtering of the data according to the rescue category with a chart and map of the filtered data. In regard to Milestone Four, I proceeded from the version that had already been done in Milestone Three. This version had the modular approach and the ranking system of rescue candidates.

Justification and Enhancement

I held on to this artifact since there was an obvious drawback for the database piece. This module was able to read records from the dashboard but didn't implement the full record management functionality that I envisioned in Module One. I changed the MongoDB data store to include features like creating, reading, updating, and deleting of specific records. Moreover, I added a small command line utility for performing these actions without needing to add any editing interface on the dashboard.

Creation and update requests undergo validation before being passed to MongoDB. These validations ensure that requests don’t contain unknown fields, nested expressions, invalid numerical values, negative age, and out-of-bound coordinates. Update actions are performed on one MongoDB record identifier and only modify fields provided in the request. Delete action shows record details and confirms deletion via an input including the mentioned record identifier. Write access is turned off by default, while database errors are shown without any database connectivity information.

I created a nonunique index for animal IDs and a separate compound index for the rescue filters. The compound index contains columns of the animal type, animal gender, animal breed, and animal age in weeks. In addition, I wrote a comparative script which reads the provided CSV file into another database, times the execution of the rescues queries, creates the indexes, and executes the queries again.

Course Outcome Alignment

The enhancement is supportive of the same outcomes 2, 3, 4, and 5 that were chosen in Module One. The outcome 2 is backed by the story, command examples, and explanation of database choices. The outcome 3 is linked to the assessment of indexes and the considerations involved. Outcome 4 is linked to the implementation and testing of reusable MongoDB component. Outcome 5 is linked to validation and controlled updating and deleting and safer errors. I haven't modified my outcome coverage plan. Instructor’s feedback and portfolio finalization will still be part of completing the submission.

Reflection on the Enhancement Process

Another challenge I faced was identifying a record. The sample of 10,000 rows contains 140 duplicate animal-id instances, as an animal may have several outcome records. To make animal_id unique means to drop the valid information. I utilized MongoDB's _id field for updating and deleting to ensure that each operation was performed on the desired outcome. Also, there was a problem of tied candidate score values. I forced reads to sort records by _id value to ensure that adding an index wouldn't impact the order of tied candidates.

The test against MongoDB 8.2.5 version clearly demonstrated the drop in the number of documents considered. Without the rescue index, all 10,000 documents were considered in each query using the existing _id index for sorting. With the indexes added, Water index considered 18 documents, Mountain considered 5 documents, Disaster considered 4 documents. All three queries returned the identical sets of records in the identical order. The indexed queries sorted the returned small sets of documents. The timings for the explain are taken; however, the single local test doesn't prove the overall performance gain.

The total number of enhanced tests, which all succeeded, were 79; among them there were eight tests run against an independent MongoDB test server, which included real-life CRUD operations, aborted delete operations, invalid update operations, and dashboard callbacks. Browsing tests showed that rescue filters, rankings, chart, and map worked with the imported sample. The project helped me see why database enhancements have to be checked for correctness and measured because an index can reduce the amount of work done by a query, but then there are the results and their safety.
